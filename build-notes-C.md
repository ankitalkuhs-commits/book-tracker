### `notificationEvents.test.mjs` and `a11yTouchables.test.mjs` — the `_ast.mjs` problem

Per T-22, both files import Package A's `__tests__/_ast.mjs` (a shared
`@babel/parser` + `js-yaml` loader via `createRequire`). That file does not
exist in this Package-C-only worktree. Per the task instructions, I:

1. Wrote both test files against a `_ast.mjs` API I designed myself (a
   minimal `{ parser, yaml, MOBILE_ROOT, REPO_ROOT, readSource, parseSource,
   parseYamlFile }` surface — the only description given in tests.md is
   "loads `@babel/parser` and `js-yaml` from `node_modules` via
   `createRequire`"; there is no further spec of its exports). Whatever
   Package A's real file actually exports, this may need a small adapter —
   flagging as a **concern**, not a silent risk: if A's `_ast.mjs` shape
   differs, my two test files' imports may need a one-line adjustment after
   merge.
2. Created a **temporary local copy** of `_ast.mjs` (this exact shape) in
   `__tests__/`, ran both test files against it, fixed real bugs the run
   surfaced (see below), then **deleted the temporary copy** before
   committing. `git status` after deletion shows only the three real test
   files under `__tests__/` — no second `_ast.mjs` was committed.
3. Verified `npm install` was needed to populate `node_modules` (fresh
   worktree, previously absent) for `@babel/parser`/`js-yaml` — this
   regenerated `package-lock.json`, which I reverted with `git checkout --`
   before committing (see "Scope check").

Bugs the local run caught and fixed while `_ast.mjs` was in place:

- `noteVisibility.test.mjs`'s "no imports" check matched the word "import"
  inside `noteVisibility.js`'s own leading comment ("Zero-import ESM
  helper..."); fixed by stripping `//` comment lines before the regex check.
- `a11yTouchables.test.mjs`'s "has a Text descendant" check only looked at
  the touchable's **direct** JSX children, so real screens that nest
  `<Text>` a level or two deep inside wrapper `<View>`s (e.g.
  `OnboardingScreen.js`'s book-result row, `LibraryScreen.js`, `SettingsScreen.js`)
  were miscounted as unlabeled. Fixed to walk the full subtree for any
  `Text`/`TextInput` element or non-blank `JSXText`, matching S58's actual
  wording ("no `<Text>` descendant").
